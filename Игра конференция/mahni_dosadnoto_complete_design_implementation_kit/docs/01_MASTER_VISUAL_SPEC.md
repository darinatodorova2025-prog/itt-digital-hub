# 01 — Master Visual Specification

## 1. Design character

Търсеният резултат е:
- premium;
- calm;
- technical;
- human;
- credible;
- conference-ready;
- visibly finished.

Не е:
- generic SaaS;
- hackathon UI;
- AI-neon;
- glassmorphism-heavy;
- flashy startup landing page.

## 2. Brand grammar

Use the real ITT Digital Hub assets/components from the repository.

Core visual language:
- deep ITT navy;
- warm/paper white;
- signal blue only for meaningful emphasis;
- thin rules;
- restrained shadows;
- compact radii;
- generous but controlled whitespace;
- clean outline icons;
- Source Serif for major editorial/display moments;
- IBM Plex Sans for UI, labels, data and controls.

## 3. Three-surface identity

### Participant
Light / paper.
Mobile-first.
One primary action.
Minimal chrome.
Narrative progress always visible.

### Live
Dark / cinematic.
Designed for 1920×1080 projector.
Big hierarchy, little clutter.
Photography is atmosphere, not wallpaper.
Readable from the back of a room.

### Admin
Operational / light.
Dense but calm.
One recommended next action.
Tables and diagnostics secondary to event state.

## 4. Layout rhythm

Preferred hierarchy:
- small stage label;
- large headline;
- short supporting copy;
- visual device / data;
- primary action;
- quiet secondary guidance.

Avoid stacking many equal cards.

## 5. Typography

Display:
- Source Serif
- used for hero headlines and major result moments.

UI:
- IBM Plex Sans
- used for forms, labels, metrics, navigation, tables, compact copy.

Rules:
- Bulgarian line breaks must be intentional.
- Live headlines must remain readable at distance.
- Participant line length should stay compact.
- Use tabular numerals for countdowns and major metrics.
- Avoid excessive all-caps except small stage/eyebrow labels.

## 6. Color behavior

Signal blue:
- current stage;
- selected vote;
- primary CTA;
- active bar;
- meaningful link.

Green:
- success / completed lens only.

Muted blue/gray:
- secondary copy;
- inactive state;
- borders.

Dark live surface:
- navy should support imagery, not bury it.

## 7. Photography

Use supplied hyper-realistic water-infrastructure imagery.

Participant:
- contained image treatment;
- never full photographic background behind dense UI.

Live:
- full-bleed or edge-framed;
- darken only where text sits;
- preserve visible infrastructure detail.

Admin:
- normally no photography.

## 8. Motion

Allowed:
- subtle phase fade;
- grouping transition;
- vote/rank reveal;
- countdown ring;
- lens completion;
- result reveal.

Avoid:
- floating particles;
- decorative constant motion;
- bounce;
- glow loops.

Support reduced motion.

## 9. Progress language

Participant:
`03 / 05 · Избираме`

Live:
subtle stage rail or compact stage marker.

Admin:
operational version of same five stages.

Progress is narrative, not a checkout wizard.

## 10. Quality test

A screen is not finished if:
- it looks like generic cards;
- image is pasted in without composition;
- visual hierarchy is flat;
- all sections have equal weight;
- CTA hierarchy is ambiguous;
- the real render is visibly less refined than the reference.
